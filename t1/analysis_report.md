# 问题一数据分析与基础调度报告

## 1. 报告范围

本报告基于附件中的 50,000 条 AI 工作负载、六区域 GPU 与 IT 功率参数、网络时延矩阵，以及 `t1.py` 生成的统计、预测和调度结果，完成问题一的结果归纳。调度采用 `t1_plan.md` 中确定的口径：GPU-hour 为需求量纲，实时任务到达即开工，弹性任务允许延后，执行区域必须满足网络时延约束，任务不可抢占、不可拆分，所有任务须在时点 2406 前完成。

## 2. 工作负载画像

### 2.1 总体规模

- 任务总数：50,000 个；
- 总 GPU-hour：5,020,786.65；
- 按统一功率映射计算的 AI IT 能耗：738,927.99 MWh；
- 三类任务数量接近均衡，各约占三分之一，但计算需求和能耗高度不均衡。

### 2.2 任务类型结构

| 任务类型 | 任务数 | 数量占比 | GPU-hour | GPU-hour占比 | AI IT能耗/MWh | 能耗占比 |
|---|---:|---:|---:|---:|---:|---:|
| RealTimeInference | 16,724 | 33.45% | 228,150.13 | 4.54% | 18,252.01 | 2.47% |
| BatchInference | 16,717 | 33.43% | 769,097.80 | 15.32% | 76,909.78 | 10.41% |
| AITraining | 16,559 | 33.12% | 4,023,538.72 | 80.14% | 643,766.19 | 87.12% |
| **合计** | **50,000** | **100.00%** | **5,020,786.65** | **100.00%** | **738,927.99** | **100.00%** |

训练任务仅占任务数的 33.12%，却贡献 80.14% 的 GPU-hour 和 87.12% 的 AI IT 能耗，是后续算力与能源协同优化的主要柔性负荷。实时推理任务数量较多，但单任务资源量较小，主要承担 SLA 约束压力。

## 3. 区域功率约束分析

由 `it_power_margin_summary.csv` 可见，东部三个区域的 IT 功率余量明显小于西部及新能源区域：

| 区域 | 最小 IT 功率余量/MW | 平均余量/MW | 最大余量/MW | 结论 |
|---|---:|---:|---:|---|
| RegionA | 18.98 | 105.84 | 264.33 | 紧约束 |
| RegionB | 18.21 | 98.93 | 260.82 | 紧约束 |
| RegionC | 17.37 | 92.86 | 254.33 | 最紧约束 |
| RegionD | 260.98 | 465.82 | 682.48 | 算力与功率承载能力强 |
| RegionE | 86.58 | 276.43 | 555.43 | 余量较充足 |
| RegionF | 66.58 | 259.30 | 471.13 | 余量较充足、存在弹性空间 |

RegionC 的最小余量仅 17.37 MW，RegionA 和 RegionB 也分别只有 18.98 MW、18.21 MW。相比之下，RegionD 的最小余量达到 260.98 MW。结果说明基础调度中真正容易形成瓶颈的是 IT 功率，而不是单纯的 GPU 总容量；这也解释了为什么问题二可以进一步研究主动迁移、价格和碳约束。

## 4. 短期预测结果

预测对象为六个区域 × 三类任务构成的 18 条小时级 GPU-hour 序列。数据划分严格遵循时间顺序：

- 训练：0–2351 小时；
- 验证：2352–2375 小时；
- 重训：0–2375 小时；
- 测试：2376–2399 小时。

总量层面的测试结果如下：

| 模型 | 总量 RMSE | 总量 sMAPE |
|---|---:|---:|
| GBDT | 1,017.40 | 29.55% |
| SeasonalMean | 1,145.64 | 35.58% |
| LastValue | 1,809.49 | 83.43% |

GBDT 相比 Last-Value 基线的总量 RMSE 下降约 43.8%，sMAPE 下降约 64.6%；相比同期均值基线，RMSE 下降约 11.2%，sMAPE 下降约 17.0%。因此，GBDT 对总负荷趋势具有较好的短期预测能力。

需要注意的是，部分细分序列存在大量零值，导致 sMAPE 对小分母非常敏感，个别序列的 sMAPE 会超过 100%。因此，论文中应同时报告 RMSE、sMAPE 和 MASE，并重点采用区域聚合及总量指标评价模型，而不应只比较单条稀疏序列的 sMAPE。

## 5. 基础调度方案

### 5.1 调度结果

- 成功调度任务：50,000/50,000；
- 未调度任务：0；
- 迁移任务：0；
- 实时任务均在到达小时开工；
- 弹性任务平均等待时间：0.00391 小时，约 14.1 秒；
- 所有任务均在 2406 时点前完成。

本次数据下，任务全部可以在来源区域本地完成，因此没有发生跨区域迁移。该结果说明在当前基础算力基准场景中，满足 SLA 的本地化方案具有可行性；但并不意味着迁移在问题二、问题三中没有价值，后续引入电价、碳强度、新能源和储能后，迁移可成为降低综合运行成本的优化手段。

### 5.2 约束验证

程序逐项核验了调度模型的约束：

| 约束 | 含义 | 违规数 |
|---|---|---:|
| C1 | 每个任务唯一分配执行区域 | 0 |
| C2 | 实时任务到达即开工 | 0 |
| C3 | 网络时延不超过任务 SLA | 0 |
| C4 | 任务在最晚完成时点前完成 | 0 |
| C5 | GPU 容量约束 | 0 |
| C6 | IT 功率约束 | 0 |
| C7 | 不占用第 2406 小时 | 0 |
| ArrivalBoundary | 不早于到达时刻开工 | 0 |

因此，当前输出调度方案满足题目规定的硬约束，可作为问题二加入电价、碳排放、新能源和储能因素前的纯算力 SLA 基准。

## 6. 结论与问题二衔接

1. 训练任务是最主要的柔性负荷，应作为后续错峰、低碳和新能源消纳优化的重点对象。
2. 东部区域 IT 功率余量小，功率是比 GPU 容量更敏感的约束；RegionC 的最小余量仅 17.37 MW。
3. GBDT 在总量预测上优于 Last-Value 和同期均值基线，可用于短期负荷感知，但调度仍以实际到达任务为输入，预测与调度保持解耦。
4. 基础调度实现了 50,000 个任务的全部可行排程，且没有发生迁移，平均弹性等待时间接近于零。
5. 问题二可在本方案基础上加入区域电价、碳强度、新能源可用出力和储能状态，将“被动满足容量约束的本地调度”扩展为“面向成本、碳排和新能源利用率的主动协同调度”。
