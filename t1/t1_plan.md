# 问题一建模框架（定稿版）

> 依据：题目正文 + 附件1.docx + 数据实测核查
> 已定决策：① 字典序分层目标；② 整数小时开工 + 精确分钟重叠；③ 实时任务"约束开放、解本地化"（选项C）

## 0. 定位与全局逻辑

问题一是三个**独立交付**：

| 子任务 | 目的 | 关键口径 |
|---|---|---|
| 统计分析 | 数据画像，支撑后续建模 | GPU-hour 为标准需求量纲 |
| 短期预测 | 证明短期负荷感知能力（仅评价） | 预测与调度**解耦**，调度用实际任务 |
| 基础调度 | SLA 优先的纯算力基准方案（Q2 基准） | 不引入电价/碳/新能源 |

已核实的三个数据结论（论文数据分析部分的卖点）：
1. AI 训练贡献 80.14% 的 GPU-hour、87.12% 的 AI IT 能耗 → 核心柔性负荷；
2. **IT 功率是紧约束**：RegionA 功率余量（Max_IT − NonAI）最小仅 18.98 MW，一个训练任务（127 GPU×0.16 ≈ 20 MW）即可吃满；GPU 容量松弛约 2.5 倍；
3. 所有区域 `Max_Facility_Power = Max_IT_Power × PUE` → 设施约束被 IT 约束**数学蕴含**，模型只写 IT 约束。

## 1. 统一符号系统

### 集合
- I = {1, …, 50000}：任务集合
- R = {RegionA, …, RegionF}：区域集合
- T = {0, …, 2405}：调度小时（2400–2405 结清时段；2406 仅结算不安排任务）

### 任务参数（i ∈ I）
| 符号 | 含义 | 来源 |
|---|---|---|
| a_i | 到达小时（0–2399） | ArrivalHour |
| τ_i | 类型 ∈ {RT, BI, AT} | TaskType |
| g_i | GPU 需求（等效 GPU） | GPU_Demand |
| d_i | 时长（小时）= 分钟/60 | EstimatedDuration_min |
| σ_i | 来源区域 | SourceRegion |
| L_i | 最大网络时延（ms） | MaxLatency_ms |
| f_i | 最晚完成时点 | LatestFinishHour（RT 为 a_i+4；BI/AT 为 2406） |

### 区域参数
| 符号 | 含义 |
|---|---|
| G_r | Available_GPU(r) |
| M_r | Max_IT_Power_MW(r) |
| P_r | PUE(r) |
| N_r(t) | NonAI_IT_Load(r,t)（逐时给定） |

### 其他
- 功率映射：p_RT = 0.08，p_BI = 0.10，p_AT = 0.16（MW/等效GPU，power_mapping 唯一口径）
- 时延矩阵：D_{σ,r}（network_latency 单向等效时延）

### 决策变量
- x_{i,r} ∈ {0,1}：任务 i 是否在区域 r 执行（唯一性：Σ_r x_{i,r} = 1）
- s_i ∈ ℤ：开工小时（实时任务 s_i = a_i；弹性任务 a_i ≤ s_i ≤ f_i − d_i）

## 3. 短期预测模型

**预测对象**：18 条小时级序列
y_{r,τ}(t) = Σ_{i: a_i=t, σ_i=r, τ_i=τ} g_i·d_i（t 时刻到达任务的 GPU-hour 需求）

**数据协议**（说明 5，严禁随机划分）：
- 训练 0–2351 → 验证调参 2352–2375 → 重训 0–2375 → 测试 2376–2399

**特征设计**（全部取自训练窗口内历史，无泄漏）：
| 类别 | 特征 |
|---|---|
| 短期趋势 | y(t−1)、y(t−2)、y(t−3)、y(t−6) |
| 近期水平 | 过去 12h / 24h 均值，近期峰值，近期标准差 |
| 周期 | y(t−24)、y(t−48)、y(t−72)、y(t−168)，hour-of-day（sin/cos 编码） |

**模型**：朴素基线（Last-Value、同期均值）+ GBDT（LightGBM / HistGradientBoosting，18 序列各自建模）；验证集调参，重训后测测试集。

**评价指标**：RMSE + **sMAPE**（或"非零小时 MAPE"，注明口径，因 18 序列零值多）+ MASE（相对季节朴素）；同时给出按区域聚合（6 条）与总量（1 条）的指标。

## 4. 基础调度模型（核心）

### 4.1 重叠量定义（分钟级折算）
o(i,t) = max(0, min(t+1, s_i + d_i) − max(t, s_i))
含义：任务 i 在小时 t 内的实际运行小时数，0 ≤ o ≤ 1。

### 4.2 约束体系
- **C1 唯一性**：Σ_r x_{i,r} = 1，∀i
- **C2 实时任务即时开工**：s_i = a_i，∀i ∈ RT
- **C3 时延**：Σ_r D_{σ_i,r}·x_{i,r} ≤ L_i，∀i（实时任务 L=20ms，选项 C：模型开放邻近迁移，解由目标保证本地化）
- **C4 完成时限**：s_i + d_i ≤ f_i，∀i；且 s_i ≥ a_i（弹性任务可延迟）
- **C5 GPU 容量**：Σ_i g_i·o(i,t)·x_{i,r} ≤ G_r，∀r,t
- **C6 IT 功率**：Σ_i g_i·p_{τ_i}·o(i,t)·x_{i,r} ≤ M_r − N_r(t)，∀r,t（设施约束蕴含，不单列）
- **C7 不占第 2406 小时**：s_i + d_i ≤ 2406（时点 2406 前完成）

### 4.3 目标函数（字典序分层）
| 层 | 目标 | 表达 |
|---|---|---|
| L0 | 硬约束全部满足 | C1–C7 |
| L1 | 最小化迁移 | min Σ_i Σ_{r≠σ_i} x_{i,r} |
| L2 | 最小化等待 | min Σ_{i∉RT} (s_i − a_i) |
| L3 | 负载均衡 | min max_r Ū_r − min_r Ū_r，Ū_r = Σ_i g_i d_i x_{i,r} / (G_r·|T|) |

求解方式（二选一，推荐顺序求解）：
- **顺序求解（严格字典序）**：先求 L1 最优值 F1\*，在 L1 ≤ F1\*+ε 下优化 L2，再在 (L1,L2) 约束下优化 L3；
- **加权合并**：F = W1·L1 + W2·L2 + W3·L3，W1 ≫ W2 ≫ W3（W1 ≥ 1e5·W2 等，按量级设计）。

### 4.4 求解算法（构造式启发式 + 局部搜索）
**Step 1 排序**：按 f_i − d_i 升序（最早截止优先）→ 次级 g_i 降序 → a_i 升序。
**Step 2 候选区域集**：R_i = {r : D_{σ_i,r} ≤ L_i}。
**Step 3 逐任务指派**：
- 实时任务：s_i = a_i，先试 σ_i 本地；若本地 C5/C6 违约（实测不发生）才查 R_i 内次优区域；
- 弹性任务：对 r ∈ R_i 按（迁移惩罚, 当前利用率）排序，逐个从 s = a_i 起扫描，找满足 C4/C5/C6 的最小可行 s；GPU 与 IT 双容量累计数组（cap_gpu[r][t]、cap_it[r][t]）随任务增量维护。
**Step 4 局部搜索**：对利用率峰值最高区域中的弹性任务，尝试重定位到低利用率可行区域（不违约才接受），循环至无改善。
**复杂度**：O(|I| × |R_i| × 平均扫描深度 × d̄)，规模 50000×6×~10×4，实际秒级~分钟级。

### 4.5 可行性论证（论文可写）
- 总量松弛 2.5 倍（需求 502 万 vs 容量 1252 万 GPU-hour）；
- 实时任务本地执行全时域 2406 小时 0 违规（已实测）；
- 构造算法每步显式检查 C1–C7 → 输出方案必然可行；
- 预期发现：东部功率余量不足迫使**部分弹性任务必须迁移**（功率驱动，而非电价驱动）——这正好是问题二优化空间的伏笔。

## 5. 收尾结清逻辑

- 2400–2405：仅执行 2399 前到达的未完成任务（含最后 24h 中 s_i+d_i > 2399 的任务）；
- 2406：不安排任何任务，仅电力/储能状态结算；
- 结清约束即 C4/C7，无需单独机制——由"最晚完成时点 + 不占 2406"自然覆盖。
